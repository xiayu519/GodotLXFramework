# 深度、碰撞与像素遮挡

## 三个独立契约

- 绘制顺序：以角色脚底与物体接地/深度锚点判定前后，不用整张图片的矩形底边冒充所有物体的脚底。
- 透明度：排在前面的物体只以实际 alpha 覆盖角色；透明空隙和图片外不能遮住角色。半透明阴影应按预期混合，不伪装成实心遮挡。
- 通行：碰撞描述实际占地与通路，通常不是整张图片矩形，也不是把屋顶轮廓当脚底障碍。

Tiled 的对象顺序或 draworder 用于静态绘制，不自动带来游戏运行时排序、导航或碰撞。自定义属性只是数据，必须由实际引擎导入器读取。不要承诺“标准 TMX”意味着所有引擎原生理解自定义桥梁规则。

## 普通建筑与树

不可进入建筑通常可保留完整 RGBA 图像，用占地碰撞和接地锚点排序：角色在前时显露，在后时被实际建筑像素遮住，靠透明边缘时仍可见。不为拆件而拆所有房屋。建筑过长、屋檐跨越可行走路径、同一结构同时需要两种深度时，才考虑有语义的部件或引擎已支持的深度方案。

至少检查前、后、两侧透明边缘与图像矩形外；树冠大于树干碰撞是合理的。给图像一个永久最高 z 值不是通用修复。Godot Y-sort 与显式 z 层要保持可比较，不能把角色和需相对排序的物体锁到互不相交的层后声称 Y-sort 生效。

## 桥与穿行结构

常见单层桥可按桥面、远侧栏杆、近侧完整栏杆/立柱/侧梁划分。按实际可见轮廓决定归属，不能只画一条对角线或把图片切成窄条。近侧立柱、侧梁残留在地面层会让腿错误露出；把整个近侧包围盒当遮挡又会挡住空隙。

简单桥面通行可采用：桥面在人物下；角色处于桥面范围时，远栏在后、近栏在前；离开桥面后回到场景正常深度。此方案的适用前提是单层桥、无桥下通行且与项目排序模型兼容。

不要把 V7 的单测试角色触发全局栏杆 z 值，直接推广成多人/NPC 通用实现。桥上和桥外角色同时出现、交叠桥梁、多高度平面或桥下通行，需要引擎已有的分层/排序组/深度方案并验证同时可见的角色。缺乏运行时支持时明确限制，不私自构建一整套游戏系统。

若尚无项目契约，可将以下作为**可选字段示例**，不是 TMX 标准字段：

| 信息 | V7 示例 | 要说明的内容 |
| --- | --- | --- |
| 部件关联 | `bridge_id` | 每个桥实例唯一，复制时全部关联一起更新 |
| 语义角色 | `bridge_role` | `surface` / `far-rail` / `near-rail` |
| 脚底锚点 | `ground_x`, `ground_y` | 图像局部像素坐标，裁切后同步更新 |
| 走面 | `walk_polygon` | 示例为相对桥面脚底的屏幕坐标；明确映射回世界的方式 |
| 抬升 | `lift_profile` | 仅视觉高度或实际导航平面，不可混淆 |

采用项目已有字段优先，不建立重复契约。平移须让部件和局部区域一起移动；翻转、旋转、缩放必须变换锚点、区域和碰撞，否则禁用这些编辑操作并说明。

## 最小运行时证据

- 普通房屋：前后排序、透明角/边、矩形外、占地碰撞。
- 桥：中间及两侧合法路线双向经过，覆盖两端进入/离开、立柱、横梁、空隙；步数由桥长和最窄特征决定，不固定成 48 步。
- 使用足底和尺寸明确的高对比测试角色；正式角色若尺寸、动画摆幅不同仍要接入复核。
- 近侧实心像素覆盖角色，空隙不覆盖；比较隐藏近侧部件的对照，避免“角色本来就不在那里”造成假通过。
- 故意放错前景层的负对照必须失败；负对照仅在隔离测试场景中，不写回成品。
- 固定像素探针可以测试绘制规则，但不能替代真实移动与碰撞。多个角色是实际需求时，必须做同时在桥上/桥外的混合位置测试。

如果只有 Tiled，可验证拼接、层次和静态样例，不能宣称运行时已通过。优先用实际导入器；隔离 QA 导入器仅证明素材和该实现可行，交付要注明正式项目尚未接入。
