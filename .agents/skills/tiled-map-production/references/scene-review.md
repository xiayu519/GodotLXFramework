# 场景设计审查

先按角色实际尺寸审查功能，再看构图。自动化能检查连通和间距，不能代替对场景合理性的目视判断。

## 优先级

1. 任务明确的玩法、通行、交互和安全边界。
2. 场景用途可信：住宅、商铺、农田、道路各有合理入口和面向。
3. 玩家能辨认目的地、入口和关键交互点。
4. 阴影、遮挡、密度和留白协调。

“不遮挡”通常是目标而非绝对禁令。入口/NPC 预留位需要可达可见；小摊可以贴房屋并受屋檐局部遮挡，只要商品、摊主位置和顾客立足点仍可辨认。不能为了避挡把摊位孤立地摆在路中或屋后。

## 各类检查

- 道路：连接入口、主要建筑和公共活动区；宽度容纳角色与碰撞半径。不要仅凭地面颜色宣称可走。
- 村口：若任务要求唯一入口，用地形、围挡或水系组成可解释的边界，并实际检查旁路。若它只是装饰地标，可以不封死地图，但须与需求一致。不需要门洞玩法时，可用开敞入口或实心地标，勿自动增加穿行建筑。
- 农田：先设计耕地与工作通道，再重复摆作物，最后围合栅栏。检查两个格轴方向、角接、缺口和入口归属。临路侧可以有围栏；问题是无理由的入口/破口、错误朝向或接缝，不是“栅栏永远不能临路”。入口优先通向住宅或劳作路径，避免随机散排。
- 作物：同种作物共享原型，行距/株距一致，少量变化有规则；不同作物与土床分别编辑。不要多张整田图各自包含重复蔬菜。
- 摊位：沿真实街面或店前组织，朝向顾客通道，给摊主与顾客留位置。菜摊与山货摊须有可读的商品差异；换名字、调色或复制同一水果图不算差异。
- 树群：按林缘、林内和孤树职责摆放；密林区域需要有层次的簇群，不用一棵孤树填角。避免整齐机械的克隆排列，也不要以很多独特图片替代合理复用。
- 建筑：门前留接地空间及角色站位；高树不能无意遮完亭子或入口。若设计不允许进入亭子等结构，碰撞与说明必须一致，不能只看画面推断可进入。
- 公共中心：树、井或广场可承担聚焦作用，但不要规定每张村图必须有中央大树。井的可使用面、通道宽度和停留位置比“几何正中”更重要。

## 验收方式

给出整图和改变区域的近景；必要时临时叠加脚底、碰撞和入口辅助线，但成品默认不保留调试标记。延续旧图时列出哪些位置明确保持不变。

遇到布局冲突，先尝试移动/转向/改变局部密度；必须更改已认可构图或玩法时，说明取舍再调整。标签、栅栏节数、树数量和小摊数量不是视觉质量的代理指标。
