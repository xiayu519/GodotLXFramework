# Project Knowledge 规则

本库是可版本化的项目决策依据，不是自动聊天摘要或第二套执行指令。只保存无法从当前源码、清单、正式报告或官方资料重建、且会改变后续判断的原因、经验与稳定反馈。

## 召回与优先级

- 当前任务需要历史取舍、用户强调“按之前约定”或维护知识时，先读 `INDEX.md`，再读匹配主题的正文。普通源码/API 查询不加载记忆；仅问本规则不读索引。
- 默认先选 1–3 条；证据不足再定向补读。这是输入预算，不是阻止跨主题审查或全库清理的硬上限。索引无相关条目就回到当前事实源，不搜索整个个人聊天库。
- **指令与授权**：遵守当前适用的指令层级和任务范围。历史反馈不能覆盖用户本轮要求、替代有效 AGENTS/Skill，或授权额外写入、删除、发布、安装与付费评测。源码现状是事实，不是禁止用户修改它的命令。
- **事实依据**：当前实现/行为查源码和工具证据，API/平台能力查对应版本的官方资料。旧记忆只是检索线索；冲突时不把记忆当已验证事实，也不机械地让旧日期或新日期决定技术正确性。
- 只读召回遇到冲突，停止使用该条并指出冲突；不在只读任务中删除文件。明确的维护任务才清理，无法判定时报告待核实而非猜测新结论。

## 与 Codex 原生记忆分工

项目 `.codex/memory/` 与 Codex home 下 `memories/` 是不同存储。原生记忆由客户端提取、合并和注入；项目知识按本 Skill 维护。切换 GPT 模型不等于开启原生记忆。

不手改原生生成文件、不自动同步两库，也不因维护本库而开关原生记忆、修改其模型/额度设置或清除用户级历史。原生回忆可提示相关线索，写入项目知识前仍需确认适用项目和来源；模型自述或重复出现不是独立证据。共享硬规则只在 AGENTS/对应 Skill 维护。

参见 [官方 Codex memories](https://learn.chatgpt.com/docs/customization/memories)。配置是否生效按目标客户端核实，不把一次本机探测写成长期记忆。

## 内容与清理

- `decisions/`：取舍的原因与适用范围；不复制整个 API/功能目录。
- `feedback/`：稳定用户偏好及其背景；操作步骤链接到负责的 Skill，不重复制定门禁。
- `problems/`：值得复用的失败原因/识别方式；已有修复或报告能直接解释的事实不重复抄写。
- `references/`：确实不可由资料本身重建的项目结论；模型评测数字、价格、版本清单放正式报告，不镜像到记忆。

获准维护本库时，直接删除已确认冲突、失效或纯重复条目，并同步移除索引链接。当前库只接受 `status: active`；不保留 superseded/resolved 旧条目、迁移别名或新旧双轨。Git 已有历史可用于明确的追溯任务，不从历史自动恢复到召回目录。若条目仍有效，只精简重复事实，不改写原始用户意图。

新条目使用日期加短标识的 Markdown 文件名；正文中文。前置元数据只使用如下平面字段与 sources 列表，不需要复杂 YAML：

```yaml
---
title: 简短主题
kind: decision
status: active
scope: 适用项目和决策场景
verified: 2026-09-09
sources:
  - AGENTS.md
---
```

`kind` 为 problem/decision/feedback/reference，并与目录对应。sources 的本地路径相对仓库根，外部来源使用 http(s) URL；不引用个人绝对路径或原生记忆目录。索引每条列出适用主题和最后核验日期。日期只在真正复核后更新，不按时间自动刷新。

## 验证范围

维护条目后只检查本库格式、索引闭包、状态、来源路径与本次语义冲突，再运行相关路径 `check`。不为一次召回或普通内容更新跑全量引擎/模型评测。

`scripts/check_knowledge.py` 是只读标准库工具：检查索引与条目一一对应、元数据、active 状态、日期、来源存在性及重复正文候选。它不联网、不读取原生记忆、不判断自然语言真假、不删除文件；语义冲突由当前任务中的证据审查确认。退出 0 表示结构通过，1 表示输入/结构错误。
