# 子代理模型与创建

以当前子代理工具声明或已提供的运行时元数据确定可用模型、能力、reasoning 和参数，不把仓库 eval profile 当作子代理模型白名单，不凭名称推定价格或兼容性。信息充分时不另做联网查询或模型探测；不足时优先查可用元数据，仍无法确认就报告配置缺口，不猜填模型或档位。

| 子任务 | 选择起点，按风险调整 |
| --- | --- |
| 明确查找、抽取、机械整理 | 能完成任务的轻量模型，low |
| 有边界的实现、调用链分析 | 均衡模型，medium |
| 公共契约、异步竞争、生命周期审查 | 能力较强的模型，high；有必要才进一步提高 |

为每个子任务选择并在创建调用中显式设置所选模型和 reasoning，不能只在回复或任务描述里声称配置。用户要求继承时按工具规则省略对应覆盖字段，说明继承而非独立设置；历史携带范围另按上下文需要选择，不为继承模型强制复制完整历史。只设置子代理，不改主会话或持久化默认配置；用户固定的选项优先。已有具体失败证据才重新分配或升级，不因等待而重复派工。

按实际工具签名调用：当前 `collaboration.spawn_agent` 的覆盖字段为 `model`、`reasoning_effort`。传入覆盖字段时，`fork_turns` 必须为 `"none"` 或正整数字符串；`fork_turns` 为 `"all"` 或省略时禁止传入覆盖字段。省略模型/档位覆盖的继承方式，也可按需配合 `"none"` 或部分历史使用。优先传必要任务说明、路径、约束与授权背景。重用不支持改配置的既有代理时，不声称已切换模型。

工具不可用或配置被拒绝时如实说明。可用且符合约束的替代方案直接继续；用户固定选项无法满足时说明缺口。不得绕过禁用状态另开 CLI/API，或把未创建的代理报告为已启动。
