# LX 子代理分工

“这个任务启动 subagent”“用子代理处理”等自然语言请求或 `$lx-subagent` 均可触发。仅提及、引用示例或询问子代理概念不构成委派；用户只要方案时只规划。普通启用请求允许判断为 0 个；明确指定数量、模型、档位或隔离要求时尊重其约束。

## 判断与数量

触发后，根据已知任务检查独立性、交付边界、重复背景、共享写入和主代理可同步推进的必要工作，不为决定是否委派先完整调查一遍。

- **0 个**：简单局部修改、强串行依赖，或交接成本大于并行及上下文隔离收益。说明理由后继续完成原任务。
- **1 个**：有独立工作可与主任务并行，或多轮图片/长日志值得隔离中间输出。
- **多个**：存在多个必要且独立的交付物。按有效分工选最少数量，不凑满槽位；同时遵守用户限制与当前剩余并发容量。

执行前简述数量、职责、所选模型/档位及理由，然后直接执行已授权工作。不要为每次委派重复询问，也不承诺总 token 必然更少。

需要委派或预演模型配置时，读取 `references/dispatch.md`。仅判断为 0 个时无需加载。

## 交接与完成

- 指定目标、输入、交付物、可写文件范围和停止条件；子代理按实际子任务加载必要领域 Skill，不因收到本 Skill 再递归拆分。
- 独立读操作可以并行；共享文件、生成目录、Godot 导入/构建和验证产物指定唯一执行者。主代理推进其他必要工作，不重复子代理的完整调查。
- 中间图片、Base64 和完整日志留在子线程或文件；返回结论、产物路径、必要证据、实际检查与未决问题。用户所需的最终预览和项目视觉验收仍要完成。
- 同一职责的连续迭代优先复用代理；主代理核对关键证据、统一集成和最终验证。验证按项目风险与变更路径执行，已通过检查仅因相关变化或新风险重跑。
