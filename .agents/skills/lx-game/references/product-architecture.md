# 产品驱动架构

新建游戏或实现具有大量同构内容的产品前读取。先确定游戏由什么驱动，再写具体地图、任务、剧情、敌人或关卡；不要把内容播放顺序翻译成一串写死的 C#。

## 驱动决策

先区分稳定机制与变化内容，并形成最小架构图：启动与 GameFlow、世界/场景、角色、UI、音频、任务、战斗、存档等模块；它们的状态所有权和依赖方向；重复流程的脚本/数据入口；高频系统与中低频编排边界。小游戏若没有重复流程或批量内容，可以直接使用少量类型化模块，不为形式统一引入事件运行时。

剧情、过场、任务步骤、音乐、场景切换、人物生成/移动、对话、条件分支和战斗入口等重复编排默认采用事件脚本。来源可以是 `bin`、`json`、`txt`、Luban 或自定义 DSL，但先经导入器/编译器归一到一个带稳定 ID 和版本的事件中间表示，再由同一个产品运行时调用类型化模块和注入的 `LX` 能力；禁止按格式建立多套执行器，也禁止把它做成第二套事件总线或服务定位器。

事件运行时按实际需求定义顺序、并行、等待、分支、变量作用域、取消、中断恢复、失败语义、存档位置、确定性时间/随机和诊断轨迹。可用 `LX.Actions` 编排中低频流程；逐帧移动、碰撞、高频战斗、AI 和网络权威由确定性的产品模块执行，脚本只发出意图或启动流程。

## 命令完成契约

脚本格式和 C# 返回类型不能隐式决定流程是否等待；每个 opcode 在 schema 中声明一种稳定语义：

- `Immediate`：同一解释器步内完成，例如设置旗标。
- `Await`：挂起当前流程，模块完成、失败、超时或取消后才执行下一条，例如必须加载完成的场景、阻断式对话、人物到达目标或战斗结果。
- `Start`：启动并立即继续，返回稳定 operation handle，例如播放无需阻断场景加载的背景音乐。`Start` 必须声明由当前脚本、World、Feature 或更长作用域中的哪一个 `Lifetime` 持有；禁止裸 `Task`、裸 `.Forget()` 或无人观察的异常。
- `Join`：按 handle 等待既有 operation；`Stop`：按 handle 请求取消或停止并观察收尾。重复 `Join`、未知 handle、所有者不匹配和已终结 handle 的行为必须由 schema 固定并可静态验证。

因此“开始音乐，然后加载场景”表达为 `Start Music -> Await SceneLoad`：音乐启动后脚本立即发起场景加载，解释器只等待场景完成；需要在稍后等待淡入或停止音乐时再显式 `Join`/`Stop`。`Parallel` 等待全部分支，`Race` 必须取消并观察落败分支；脚本、切图、死亡或重开结束时，所有未完成 operation 必须按所有权规则转移或闭合，不能遗留后台任务、信号订阅或取消注册。

实现优先复用 `ValueTask`、`LX.Actions`、框架 `Clock`/调度与 `Lifetime`；不要只为语法方便引入第二套 PlayerLoop、全局调度节点或生命周期容器。只有基准证明事件运行时的异步状态机分配是实际瓶颈，并且候选库能接入上述所有权、取消、异常与诊断契约时，才评估替换底层 awaitable；脚本的 `Immediate/Await/Start/Join/Stop` 语义不随库变化。

## 实现与扩展门禁

先搭执行骨架和模块契约，再用少量代表场景证明脚本、模块、状态和生命周期可以组合；这个架构契约切片不是逐剧情开发模板。契约稳定后批量导入或编写全部脚本和数据；填充期间对全部脚本/数据做静态闭合检查，运行时只验证受影响契约组。内容冻结后再统一运行引用、操作码、状态转换、资源、存档与行为场景的全量验证，禁止每增加一段内容就重跑全部产品场景。

同类的第二个地图、任务、敌人、对话或战斗入口应只增加脚本、Luban 或内容事实，不修改执行运行时。确需新增代码时先记录它是新的通用机制还是有证据的产品特例，禁止用内容名称分支逃避建模。

## 公共机制缺陷优先归因门禁

新游戏或复刻实施中出现单点症状时，先把它作为公共机制缺陷的候选，而不是立即在当前人物、地图、任务或剧情上打补丁。用最小复现和同路径的另一份代表内容确认边界，并沿“脚本/数据 -> 类型化模块 -> 引擎适配或跨引擎本地化 -> LXFramework -> 引擎/平台”定位最窄的真实所有者；同时保留一个不受影响的对照，防止把合法内容差异误判成公共 Bug。

- 若同一契约下的第二份内容也失败，或证据指向共享状态、时序、坐标/单位、输入边沿、碰撞、动画、序列化、资源生命周期、异步完成语义或平台适配，则在最低共享层修复，并回归该共享层映射的受影响内容；禁止按内容 ID 增加分支，也不把局部回归扩成无关产品全量回归。
- 若共享契约与代表内容均通过，且证据证明只有该内容事实异常，则修正脚本、Luban 或内容数据，不为单一异常扩张公共架构。
- 若确有不可推广的产品特例，必须记录判定证据和适用边界，通过显式类型或数据规则表达，不能伪装成公共机制。

当现有证据无法决定来源的预期行为、目标引擎的等价语义、缺陷所有层、兼容取舍，或修复会改变公共契约时，立即暂停修改；向开发者汇报已确认事实、未决项、可选方向及各自影响，等待明确选择后再执行。可以继续做只读取证，但不得猜测性修改架子、增加兼容分支或写死当前样本。

完成证据至少包括：驱动架构与状态所有权明确；所有脚本可解析且引用闭合；`Await` 的阻断顺序、`Start` 的并发继续、`Join/Stop`、超时、取消和异常路径通过；代表架构契约通过；内容冻结后的批量验证通过；死亡、胜利、切图和重开后脚本 operation、模块、资源租约与池借出闭合。
